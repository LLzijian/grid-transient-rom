# TASK4：规划内自主推进、证据接受、无益回退、改向审批

本文件是执行机制。科学设计见 `../TASK4.md`；授权及数据保护以 `../AGENTS.md` 为准。旧TASK2的逐轮限制不自动继承。

## 1. 总循环

```text
读取有效规划/最新用户指令/状态/实际进程
  ├─ 未启动授权 → 只读准备，等待用户启动（不是自动开训）
  ├─ 有方向修改待批 → 停止科学实验，询问并等待明确认可
  ├─ 用户暂停 → 保存退出
  ├─ 资源或必要数据确实不足 → 记录具体BLOCKED原因
  └─ 已授权、规划内、资源可用
       → 选择当前最有信息价值的完整问题
       → 写简短思路卡及预算/对照/共同评价
       → 实现+必要QA+合成烟测
       → 完整实验：表示/联合适配/压缩/自主精调（按问题所需）
       → 独立只读复核
       → 有价值：accept或retain；无价值/不确定：reject/inconclusive并回退
       → 关闭阶段，释放未用预算，更新能力和下一决策
       → 若仍相信已批准路线可推进：自行进入下一轮
       → 若判断核心方案有问题并建议新路线：提交修改单，暂停询问
```

## 2. 一轮研究什么

研究“这一思路在当前范围内能实现什么效果”。不得把“误差必须再降10%”当每轮存在理由。参数设置、剪枝和联合适配可在同一协议内完成，不能拆成二十个孤立修补。

必要字段：问题；比较；共同信息；学习/固定对象；完整单次初始化终点；数值与严重事件规则；参数设置范围；总预算和停止规则；各结果对应的下一决策。

保留最多三个主臂P/A/U，首轮单种子。初期实现不足可先完成P的端到端缩小版本，再按同一大规划完成对照。缺失对照不可包装为模块贡献已证明。

## 3. 运行和预算

1. 核对 `../kiki` 的两套数据目录和M3资产，只读源代码，不直接启动KIKI脚本。
2. 起点为当前accepted代码/模型。无已接受模型时用已测工程初始版本，不捏造基线分数。
3. 每臂提前预留最终自主精调和冻结评价预算；至少35%的研究计算供最终阶段及其必要评价。不得因N尚未完美而永远不进入C/D。
4. 用实测小步成本安排可执行里程碑。只用TRAIN/内层TRAIN决定有限扩展，不把开发集反复当训练反馈。
5. 阶段关闭余额返回父池。改名不能重置已花成本；原协议关闭后不能重判或偷续。
6. `project.py run`同步监管进程、保存日志及成本。进程内部每秒资源守卫继续运行；根代理对健康长任务默认每900秒（15分钟）查询一次，读取`configs/project.json`的`budget.poll_seconds`，只取运行状态与最新1条日志。进程结束、异常或用户主动询问可提前查看；不得为普通健康检查载入模型或重算科学指标。
7. 即将超限由子进程先保存last，监管器必要时终止进程树；若模型保存失败，报告真实状态，不以旧文件冒充最新。

2026-10-07按用户要求降低token消耗：`progress_reporting`是代理执行约定，不是新的常驻调度器或自动通知服务。普通检查结果留在日志，不逐次发“又完成20步”等重复汇报；只在已登记里程碑（当前100/200/400步）、阶段完成、异常或需要用户决策时对外汇报。一次检查跨过多个节点时合并为一条有实际信息的更新。该偏好不修改逐步训练日志、每5步检查点、固定TRAIN监控面板或冻结开发评价节点，也不要求重启当前训练。

## 4. 接受前的最低复核

并非每轮全套重做：只检查被改动的接口和声称的收益。

- 源数据/ID/尺度正确、没有TEST载荷或未来输入；同队列、同时间、完整分母。
- 代码确实实现思路，p/te/omega单位一致，部署只编码一次。
- 功率恒等式与梯度检查通过只是结构实现正确，不是模型保真。
- 数值敏感区间隔离，失败ID保留；不重组一个更小分母叫“全量通过”。
- 对重要新收益用缓存独立计算一次；人/工具不独立必须说明。
- 预测模型、正式判稳器、符号公式各自确认，不能替代。

## 5. 什么是进展

**接受实现：**完成原规划所需的新模块，通过相关测试，可供下一实验使用。不会因此产生虚构预测分数。

**接受模型：**有可信、相关的能力收益，或在精度范围内更低复杂度/更快。预先声明的严重风险不被平均分抵消。仍可保留标记为研究用途的互补候选。

**接受诊断：**明确改变下一自主实验的选择，不接受无决策作用的无尽解释。对受预算限制的结果不用“模型族失败”。

每轮报告四个独立状态：证据、能力、优化、晋升。公式压缩失败不会删除N成果，但也不会把N改名为S。

## 6. 无进展如何回退

- 候选输出写 `artifacts/T4_XXXX/<arm>/`，永不覆盖accepted模型。
- 代码先建立版本锚点：独立TASK4 git提交或 `scripts/snapshot.py create`。
- 失败代码在提交或快照中保留；再用只影响本轮文件的git切换，或带expected-current保护的快照恢复。
- `project.py close-loop --decision reject` 回退模型活动指针；**它不会自动修改工作树**，根代理必须另完成代码恢复并在报告中记下证据。
- 不删除报告、数据派生记录、梯度失败、运行成本及新实现的有用测试。代码实质改进可单独接受，预测候选仍拒绝。
- 无当前accepted模型时，回到工程基线，保留accepted_candidate=null，不冒充现有成功模型。

## 7. 路线改变的停点

单次失败先判断是否是实现/优化或已有对照能解答，不急于改向。

一旦准备宣告核心路线有问题并采用新方向：关闭当前loop（可为inconclusive）；冻结有效端点；写 `proposals/DIRECTION_XXX.md`；执行 `project.py propose-direction`；给用户说明“证据→为何不是普通修复→首选新方向→预期代价→请求认可”。

**此刻不再启动新训练、压缩搜索或新FOM。**只允许解释已存证据及必要保存。继续沿旧思路额外探索也应等用户答复，不能消耗预算削弱审批的实质作用。

用户明确同意后，将原话写入approval事件，再改路线相应部分和下一协议。不同意则保持暂停，不能偷偷执行备选方向。允许的参数范围内调整不需要该审批。

## 8. 总任务何时结束

- L1和显式T4-S按所声明范围完成，L2形成诚实结果/仍有明确缺口；最终报告不得用“完成”掩盖缺失。
- 预算耗尽→BLOCKED_RESOURCE；缺必要本地数据→BLOCKED_DATA；新方向待批→WAITING_USER_DIRECTION_APPROVAL。
- 子任务成功或失败都不是当然终止父任务。运行时会话退出→INTERRUPTED_RUNTIME，后续需要实际代理恢复。

## 9. 软件状态工具的边界

状态工具保存代理的决策，不会自动判断科学正确性、替代独立审查或向ChatGPT推送通知。`approve-direction`是记录人工认可的动作，执行代理不得自己杜撰instruction。操作系统文件权限尚需用户环境保证；代码的路径限制是工程护栏，不声称防御恶意代理。
