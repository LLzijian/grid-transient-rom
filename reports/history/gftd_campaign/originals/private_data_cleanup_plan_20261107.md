# private_data 整理与保留方案（2026-11-07）

**建议将 private_data 收回为数据集目录，实验大文件迁到 artifacts，公开摘要继续放 reports/results；旧实验按“最小保留包”精简。** 这是一份待执行方案和目录清单，本轮未移动或删除原文件，也未修改当前训练与运行配置。

## 1. 盘点结论与目标

本次按文件名、逻辑大小和源码引用盘点，共279个顶层目录、2个根部JSON。与上一轮278个相比，本次已出现当前研究的`gftd_fit297_20261107`目录。研究仍在推进，此次扫描不是原子快照。

可访问文件至少79.78 GiB，其中5个`ieee39_*`数据集目录合计3.51 GiB。按后缀统计，`.npz`为59.85 GiB，`.pt`为0.093 GiB；主要空间应从轨迹、预测和派生数组中查找，而非只删日志或训练权重。

有27处访问错误、165个联接未跟随，大小按下限报告。无法读取不能当作空目录。目录用途由名称与抽查引用初判，尚非逐文件删除资格审查。

目标分开验收：

- **目录职责**：最终private_data保留数据集及其索引、划分和生成来源；历史研究产物有明确归属。
- **空间回收**：删除经过核验的重复文件和可重建副产物；移动到同一磁盘本身不释放总空间。
- **研究连续性**：当前来源链、受保护模型、唯一输入和决定性证据可用，旧结论不因整理被擦除。

## 2. 最小目录划分

| 位置 | 存放内容 | Git处理 |
|---|---|---|
| `private_data/` | 5个主要数据集目录；另有唯一仿真数据时，单独登记其数据身份与访问范围 | 数据内容留本地，公开清单按现有规则 |
| `artifacts/<原目录名>/` | 实验模型、检查点、原始预测、分析数组，以及对应执行日志和回执 | 整体忽略；必要源码与小摘要另行入库 |
| 现有`reports/`、`results/` | 协议、结论、逐事件指标、来源哈希、模型与科学决定 | 延续现有选择性归档 |
| `.tmp/` | 测试生成文件和可重建缓存 | 忽略；作业结束后清理 |
| `local_backups/` | Git整理与迁移恢复备份 | 忽略；按恢复价值单独决定期限 |

先沿用旧目录名迁移，避免同时重排实验内部文件。新实验从一开始写入上述职责目录；运行回执归属相应实验，不另造一套中央运行档案。历史脚本若只留在private_data，须先保存可复现源码，再清理其生成物。已被Git跟踪的小模型或模态证据须保留明确的选择性归档位置，不能因artifacts整体忽略而漏掉。

## 3. 旧实验保留什么、能删什么

| 材料 | 处理原则 |
|---|---|
| 原始数据、固定划分、唯一仿真结果、冻结输入 | 保留。当前FOM=0、val/test关闭，不能假定以后随时重算 |
| 已接受模型、当前候选及其来源 | 保留完整模型和必要来源；下游身份检查所需状态一并保留 |
| 支撑正面或负面结论的材料 | 保留协议、精确源码/配置/种子、数据身份、关键逐事件结果、完整分母、曲线、三决定与成本 |
| 决定性检查点 | 保留最终端点、明确采用的历史端点、用于机制比较或优化充分性判断的必要端点；各比较组和必要种子分别保留 |
| 未被采用的中间检查点、Adam/RNG | 确认无当前引用、无恢复用途、无独立证据职责后，可删除；不要求每16步的状态永久保存 |
| 大型预测和派生数组 | 若能从保留模型和合法可读输入确定重建、成本可接受、且无需重开val/test或新增FOM，可只保留必要摘要与重建命令后删除；否则保留 |
| 重复副本 | 必须按字节哈希确认相同，并保留可用的唯一副本及有效读取路径；文件同名或大小相同不够 |
| 失败尝试 | 保留失败原因、关键回执、相关源码与最小证据；其中可重建的重复测试输出可删。失败标签本身不决定整目录删除 |
| 单测临时目录、缓存、重复标准输出 | 无活动作业使用且确认由测试生成后，可优先清理；若日志是唯一成本/失败证据，先提取保留 |
| Git备份与heartbeat | 迁到备份或对应运行记录位置，不能当普通测试缓存一起删除 |

“最小保留包”是上述材料的文件选择，不要求为每轮新建一个压缩包或管理平台。保留失败结论与必要证据，不等于永久保留失败尝试的全部临时文件。

## 5. 执行顺序与回收预期

1. **确定保护集合与停止写入边界。** 按当前作业、候选谱系、报告引用核对；有活动写入者或状态不明的路径跳过。先让后续新产物走正确目录。
2. **先清小型测试杂项。** 工程测试与可访问q*目录的可见总量约2.82 MiB；这些是候选总量，不是已核准删除量。7个q*根无访问权限，保持unknown。Git备份约7.15 MiB、heartbeat约0.032 MiB应归位保存。此步主要减少目录数量，不解决大空间问题。
3. **迁移无当前依赖的已闭合实验。** 使用明确旧路径→新路径清单，逐文件核对大小与SHA256；核对报告和消费者后再移除源副本。容量不足时同卷逐目录迁移，但必须有可逆日志和逐项核验，不一次性扫整棵目录。目录联接只在单独验证兼容时使用。
4. **精简已迁移实验。** 第一组大文件审查对象为`memory_transport_20261029`约4.23 GiB、`checkpoint_selection_20261030`约3.14 GiB、`force_exchange_20261028`约2.81 GiB，合计约10.18 GiB。这是审查范围，不是预计全部可删；保留端点与决定性证据后逐文件计算可回收量。下一组再看0099/0101/0102/0103等轨迹数组。
5. **最后迁当前依赖链。** 等本轮阶段闭合，验证版本化路径配置和来源身份兼容；保留旧位置与新位置的对应关系。旧报告不批量改写，历史复现按迁移清单恢复其所需布局。
6. **完成后立规矩。** 更新输出路径约定与忽略规则；闭合实验按最小保留包收尾，测试缓存有结束清理，禁止新运行把非数据集产物继续写入private_data。

每批实际删除前提供路径、大小、保留替代物、重建或无依赖依据，并先转入有清单的隔离区。迁移不等于备份；隔离也不释放磁盘，只有最终删除才计入回收量。隔离期建议14天，期满且复现/读取核对通过后再永久删除；需要立即腾空间时单独批准具体文件。

未完成逐文件核验前，不承诺释放若干十GiB。可见数据表明，主要精简机会在约59.85 GiB的数组中，而非小型测试目录。
