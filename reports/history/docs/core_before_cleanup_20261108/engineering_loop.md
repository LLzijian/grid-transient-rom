证据规则见 [research_policy](research_policy.md)；前序闭环文档存档于

## 1. 从当前状态与授权边界开始

先核对真实授权、状态、来源 commit、未完成作业/归档、当前架构与四指针（`main code`、`working_candidate`、`incumbent`、`protected anchors`）。
`PAUSED_BY_USER` 或未释放新 Run 时仅做已授权整理、一级算法设计、受控数学单测与代码审查；不偷跑资格训练。
状态未知先对账，不能重复调用已有不可确定 Job，也不能把示例快照当实时状态。

## 2. 架构简报与 Campaign

涉及状态空间、生成泛函、结构发现算子或主要训练目标改变，先更新 [一级算法设计](architecture_design.md) 与 [架构简报](gftd_kuramoto_architecture_brief.md)。
Scientist 给最小主方案、竞争解释和简单基线，Reviewer 挑战冻结版本，root 记录采纳理由及真实模型回执。
Campaign 维护范围、假说、架构引用、竞争解释、Run 树、暴露谱系、当前证据及下一判别问题。
GFTD 的受控恢复、跨生成机制检验和 IEEE39 条件内辨别安排见 [Campaign](../campaigns/gftd_kuramoto_discovery_20261106.md)。
Stage A/B/C 是该算法的步骤，各路线依据问题选择必要的科学工作。

## 3. Run 类型由问题决定

| 类型 | 主要职责 | 改变科学判断的关键结果 |
|---|---|---|
| `probe` | 检查实现、数学性质和机制可检验性 | 恒等式或嵌入错误、探针失灵、信息不足 |
| `adaptation` | 检查合理优化和初始化能否改变判断 | 欠优化解释变强或变弱，定位具体瓶颈 |
| `discrimination` | 匹配容量、初始化及合理适配机会，区分竞争机制 | 不同机制的可观察预测分离 |
| `confirmation` | 检查正、负、混合结果在主张范围内的重复性和效应精度 | 结果范围、不确定性或等效判断改变 |

这些是 Run 目的。一个 Run 可含多 Job 或 trial，解析反例和廉价探针可直接服务对应问题。

每个新科学 Run 前按既有要求实际调用 Scientist（`gpt-6-astra`），保存简报、来源及 root 采用记录。

## 4. 运行前最小协议与实现契约

1. **运行前协议**。写清问题、父候选/架构、只改变什么、合法输入和历史暴露、匹配对照、主要估计对象、关键事件守卫、数值资格、证据产物及确认设计，按 [模板](../templates/run_protocol.md) 登记。
2. **有限计划**。预先定义比较、初始工作窗口、适配触发条件及上限、停止/转向/重开条件和成本范围。追加适配须针对具体竞争解释，保留已用机会，关闭余额不转移。
3. **实现与冻结执行**。Modeler 核查因果输入、单位、功率、已知极限和适用域。Experimenter 使用冻结源码/配置，记录数据身份、初始化、RNG、优化器、数值与逐事件结果，遵守 [runtime](../agents/runtime.md) 的单写者、资源互斥与未知 Job 对账规则。

## 5. 五轴独立解释与防无止境调参

| 观察 | 合理下一动作 | 禁止跳跃 |
|---|---|---|
| 实现/功率账/数值证据无效 | 有界 repair 或结束无效 trial | 宣布生成泛函算法族被否证 |
| 弱形式 Gram 矩阵秩亏、结构门振荡 | 规范标准型消歧 / 等价类合并分析 | 盲目拉长伴随 ODE 训练步数 |
| 梯度健康但层级门尚未坍缩、充分性未知 | 有针对性的 adaptation 或暂存 | 把健康当充分、或把未坍缩当机制无效 |
| 单次匹配辨别正收益（如漏检率改善 + 拓扑恢复） | 预算内观察；规划结构稳定性 confirmation | 直接声称全局唯一物理定律或自动晋升 |
| 单次无收益或混合结果 | 按充分性、探针和区间精度选适配、辨别、确认或暂存 | 自动否定或无条件追加训练 |
| 有效匹配、合理适配及相符确认下，区间支持实践等效 | 限定实例与协议的性能等效判断 | 推出物理机制不存在 |
| 精确数学反例且经独立复核 | 否定对应全称命题并关闭该支线 | 越界扩大到未覆盖的动态调制模型族 |

实践等效须预登记实际意义界值 $\delta>0$、指标方向、估计对象和不确定性方法，整个区间落入 $[-\delta,\delta]$ 才支持该范围内判断。区间过宽保留未决。
确认需求与晋升资格分开记录，首轮正、负、混合结果均可触发确认。种子重复衡量优化随机性，已暴露 train 的重复使用须披露。
结果后改变问题、目标或判据，应保留旧解释，另作前瞻修订。

连续两个 Run 仅有标量微调或工程修复而未减少重要不确定性时，触发内部结构复盘。
root 判断可区分预测、重复证据与更便宜的替代试验，决定继续或暂存并写重开条件。
范围内已授权工作按有限协议自主推进，固定次数只触发复盘。

## 6. 闭合、归档与历史兼容

每轮结束独立给出**代码、模型、科学**三个决定，更新 Campaign 的竞争解释表与主张台账，按 [research_policy](research_policy.md) §6 选择性提交、普通推送并核验远端与本地原字节回执。
按 [闭合模板](../templates/run_closure.md) 保留负结果和工作候选，保护已接受锚点，分别收尾科学、执行与预算状态。归档未确认先对账，再进入下一 Run。
旧 `NOT_RETAINED` 保留不晋升含义，旧余额关闭，历史产物与协议按当时身份解释。
旧 runner 与历史结果保留原口径：`optimization_unresolved=False` 仅映射为 `optimizer_health=healthy` 且 `optimization_adequacy=unknown`；能力分层 L1/L2/L3 与五轴证据判断严格分离。
