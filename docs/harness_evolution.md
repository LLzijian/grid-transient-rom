# harness 自身如何改进

科学循环更新假说、算法与证据；harness 循环更新提示、工具、分工与记忆。
两者使用不同变更记录。修改流程不能改科学评价合同、封存数据、用户权限或历史分类。

## 1. 借鉴 Harness² 的范围

提出一个具体流程缺陷 → 对照观察 → 选择有证据的改变 → 提炼带适用条件的经验。
单次成功/失败是弱证据；被采用的整体可能包含无贡献改动，被拒整体也可能包含有用改变。
KEEP_BASE 是合理结果。多个同模型 agent 赞同不构成独立真值。
不复制其任意改 guardrails 的权限，也不把罕见严重错误按出现频率直接视为噪声。

参考：[Harness²](https://github.com/google-research/harness2)、
[论文](https://arxiv.org/abs/2610.14224)；本文是本项目迁移设计，不声称原框架已验证物理科研能力。

## 2. 轻量评估

每次只提一个主要过程改动及预期行为；保留现行版本作对照。
用冻结的历史决策片段和另外保留的未参与规则编写案例比较；不重跑长训练来评价文字风格。
成套发布覆盖关键风险矩阵；局部改动只验证受影响行为及一个未参与修改的相关案例，
不机械全量重测。风险矩阵包括：首轮无收益但优化不足、合法零边界、同分异错、均值改善但关键事件退化、
数据暴露伪确认、不可辨识机制、精确结构反例、用户暂停、未知 Job 重放和写路径冲突。
工具单测只验证程序行为，不证明 agent 能设计优美算法。

主观察是：错误否定/错误晋升是否减少，是否提出真正区分解释的下一步，是否发生权限/状态错误，
在相近资源下可审查知识产出是否改善。记录 token、人工纠正、延迟和重复工作作为成本，
不以文档数、Run 数、图表数或自评分为进步。
案例反复使用会过拟合，记录暴露；新增保留案例、盲化版本、交换顺序，并复核分歧。
有限 shadow trial 只能在用户已恢复科学运行且该工作本来有科学价值时进行。

## 3. 只保留可复用的经验

每条经验写：触发条件、支持证据、反例/局限、推荐动作、重验条件；无范围的永久禁令应删除。
运行事实留在报告，假说变化留在 Campaign，过程经验留在本文件关联记录，避免三份同步日志。
同等效果优先更短的常驻规则；按任务读取材料，不把整个历史塞进 AGENTS。
升级须有 diff、来源 hash、已测行为与未验证能力；安装和采用分开，旧结果不追溯重判。
