# 研究证据、双档案、预算与 Git 政策

本文件是证据、档案、预算与归档的唯一规则来源；执行流程见
[engineering_loop.md](engineering_loop.md)，科学任务设计见 [../kiki.md](../kiki.md)。

## 1. 三类标准分开

**证据有效性（必须）。** 因果输入、train/val/test 隔离、单位与状态定义、真实标签与
时间区间、适用的数值资格、可复现配置、分母与未决处理。证据有效性失败只影响该证据，
不自动否定整个想法或无关结果；数值/实现失败记为 invalid，不能当作物理假设被否证。

**探索价值。** 改进、退化、结构简洁性、新能力、训练行为、成本与不确定性都算信息。
候选可以不在所有指标上胜出；不追未登记子群，不把探索性收益升级为确认结论。

**主张/采用资格。** 预先登记的具体门槛在观测结果后不得降低。未过门表示该主张不成立，
不等于全部科学价值为零；安全/关键事件退化不能被平均指标抵消。探索性 Pareto 保留
不是晋升；历史门与分类保持不变。

## 2. 双档案与四个指针

**可用模型档案（受保护）。** 已接受、有明确评价合同与适用范围的历史锚点。替换需
完整匹配的评价合同、关键误报/漏检身份、数值资格与独立复核；晋升是 root 的明确
科学决定，执行代理只落实。可用只表示在原研究口径下被接受，不自动等于可部署或
高阶稳定性保证。

**科学候选档案。** 保存精度、关键事件、复杂度与成本之间不同取舍的冻结端点。记录
artifact+hash、来源 commit、设计引用、父候选、数据与评价合同、指标与错误身份集合、
数值未决、复杂度、计时来源与缺失项；缺失写 null 不写 0。同口径下做非支配比较，
不把数值、错误集合与成本揉成一个总分；错误数相同但身份不同可以是互补。
未完整评价的端点只能标 evidence_only。

四个指针相互独立：main 代码、working_candidate、可用模型/incumbent、保护锚点。
关闭 Run 不得自动把 working_candidate 重置为 incumbent；下一研究起点由 root 依据
证据选择。换起点/换来源须显式登记谱系与信息暴露，不用新编号隐藏历史失败。
代码、模型与科学假设是三个独立决定，分别记录；一个 Run 的模型未晋升不自动否定
其代码质量或科学假设，反之亦然（见 engineering_loop §8）。

## 3. 数据与信息边界

- 原始 val/test 关闭；旧已消费 test 永久退出模型选择。新 test 须在模型、初始化器、
  判据与声明范围冻结并获得用户授权后一次性使用；打开仓库不构成授权。
- 新 FOM 条件为 0；不新生成高阶训练数据；不购买资源或建云任务，除非另有明确许可。
- 部署输入仅 100 ms 内合法 δ、ω 历史、末点真实 p₀ 与冻结物理常数；不得使用未来
  真值、事件身份、故障元数据、逐事件方程或测试时拟合。训练中使用的真实标签、辅助
  物理量、自由隐轨迹只用于训练，不得进入部署或独立评价输入。
- 分母按原定义保留：无窗/不可初始化/数值未决事件不删除、不补造；真实区间与 8 s
  分类是两套报告，不能混用。
- 私有数据、原始轨迹数组、检查点与 Adam 状态按既有本地保全规则管理；敏感数据、
  密钥与实时 PID 不上传。

## 4. 预算与账目

- 用户已取消进程数量、单进程时长、进程秒与父进程总小时额度（2026-10-21）；
  实际 wall/CPU/GPU 成本仍须记录，未知写 unknown，不伪造有限额度或历史额度。
- 每个 Run 仍登记有限科学工作量与停止规则（比较组、种子、更新数、允许修复、
  延长触发与决定）。没有额度限制不等于无限延长：判断依据是学习曲线、残差与能力
  变化，而不是"还能继续跑"。
- 已登记预算类别（如 formal / QA / repair / replay）不得挪用；观测结果后不得降门。
  关闭阶段的剩余额度不自动转入下一 Run；历史退休余额（如旧 0099/0098/0101 类别）
  不因换路线而复活。若某个 Run 登记 1848 = formal1536 + QA108 + repair108 +
  replay96，它只对该 Run 有效，不是后续 Run 的默认额度。
- 同一架构/目标/来源谱系的延长次数绑定该谱系；换编号、换种子或重启 Adam 不重置
  延长记录。只有明确改变科学问题并记录理由才另立判断。
- 成本与科学结论分开报告；同精度成本必须有同数据、同步长、同时长、同硬件实测，
  缺失即"未比较"。

## 5. Git 归档与发布

仓库：https://github.com/LLzijian/grid-transient-rom.git

每次执行产生或改变设计、实现或实验结果后，选择性提交并推送；接受、拒绝、失败、
未决与阻塞结果同样归档。只读检查无新材料不必空提交。长作业在阶段边界同步。

1. **保存可耐久记录。** 设计/协议与修订、必要源码/配置、决定性结果（含不利结果）、
   数值资格、评价范围、成本、三个决定、复现命令与来源哈希；Campaign 卡与 Run 树、
   current_state 随状态变化更新。
2. **选择证据。** 报告、必要表格/图与小体积证据入库；原始数据、缓存、临时输出、
   中间检查点、私有数据与权重默认留在本地或原存储，并在报告中给出路径、哈希与
   获取/复现说明。不入库不等于可删除证据。
3. **审查与提交。** 显式暂存相关路径/片段；禁止把无关工作树改动、private_data/、
   密钥或大体积二进制扫入提交。先提交证据，再回退活动代码；只能 git revert
   明确回退，禁止 force push、reset --hard、git clean 清除未归档研究。
4. **推送并核验。** 普通非 force 推送；核验远端分支指向预期 commit。本地 commit
   不等于已同步；推送失败保留 commit 并记录准确阻碍与重试动作。
   恢复运行时先对账未完成归档，再开始新实验。

归档不创建新注册表、不改科学门、不授予训练或 test 权限。

## 6. 最小发布包与状态

**Campaign 卡**：假设、当前信念、替代解释、已排除解释、Run 树、仍需证据、下一
最有判别力的 Run 与适用范围；不做进度流水账。

**每个 Run**：

- **protocol/mechanism card**：问题、机制卡（见 kiki.md §6.4）、来源与信息范围、
  对照、评价口径、预算、停止与延长规则、确认条件；
- **report**：问题；真正变化；关键失败；三种解释（支持/不支持/未决）；代价与
  下一动作；一句话结论；
- **three decisions**：代码、模型档案、科学假设三个独立决定，附证据与范围；
- **evidence**：足以复算摘要的逐事件数字、曲线/残差、方程、数值资格、成本与失败
  记录；
- **identity**：source commit、checkpoint/model hash、数据与尺度、命令/环境/种子、
  归档 commit 与推送核验。

任务状态只使用 RUNNING / COMPLETED / BLOCKED / PAUSED_BY_USER /
INTERRUPTED_RUNTIME；Campaign 状态使用 active / supported_within_scope /
falsified_within_scope / unresolved / paused_review；Run 结论使用
continue / supported_within_scope / mechanism_null_within_scope /
falsified_within_scope / unresolved / abandon。三者分开记录。
current_state 保持约一页：任务状态、当前 Campaign/Run 与指针、下一可执行动作、
恢复命令、累计成本与未决阻碍；不写日记。

## 7. 历史与更正

历史报告、分类、checkpoint、失败证据与已关闭预算保持原身份；新结论只在追加的
更正说明中更新，不擦除原文、不重判旧结果。历史授权记录见
[research_execution_20261028.md](research_execution_20261028.md) 与 docs/history/；
规则更新不改写历史授权范围，也不追溯扩大权限。
