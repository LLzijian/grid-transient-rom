# 科学闭环：设计、适配、辨别、确认

保留 Campaign → Run → Job；算法实例、trial 和 checkpoint 用 ID/父引用记录，
不为每种对象再造管理层。规则来源见 [research_policy](research_policy.md)。

## 1. 从当前状态开始

先核对真实授权、状态、来源 commit、未完成作业/归档、当前架构与四指针。
PAUSED_BY_USER 时仅做已授权整理/设计/代码审查；不恢复训练或新建科学 Run。
状态未知先对账，不能重复调用已有不可确定 Job，也不能把旧示例当实时状态。

## 2. 一份架构简报服务一个可检验方向

涉及状态、闭合族、推断原则或目标改变，先走 [一级算法设计](architecture_design.md)。
Scientist 从第一性原理提出学习问题、最小结构和竞争解释；Reviewer 对冻结版本挑战；
root 记录采用理由。模型身份须为宿主真实回执，不从角色名称推断。
小型实现修改直接引用现有简报，不重复宏观论证。

Campaign 最少维护：假说与范围、架构版本、竞争解释、已排除解释、Run 树、
当前证据和下一个有判别力的问题。历史索引明确标 retrospective，不能补造预登记。

## 3. Run 类型由问题决定

| 类型 | 主要目的 | 什么结果改变判断 |
|---|---|---|
| probe | 验证实现/数学性质和机制可检验性 | 等价嵌入错误、探针失灵或不可辨识 |
| adaptation | 检查合理优化与初始化能否改变结论 | 欠训练解释变强/变弱；明确优化瓶颈 |
| discrimination | 区分竞争解释 | 相同容量/初始化/机会下不同机制预测 |
| confirmation | 检查主张范围内的重复性与效应精度 | 正/负/混合结果的范围与不确定性改变 |

上述是 Run 目的，不是固定流水线或每方向都要跑四次。一个 Run 可含多 Job，
一个 Job 也可能含多 trial；真实进程身份与科学比较身份分开。
每个新科学 Run 前按既有要求实际调用 Astra，保存简报、来源及 root 采用记录。
工程任务依附它所解锁的科学问题，不计作独立发现。

## 4. 运行前最小协议

写清问题、父候选/架构、只改变什么、合法输入、匹配对照、主要估计对象、
关键事件守卫、数值资格、适配窗口、停止/转向条件、确认设计和证据产物。
可用模板不是强迫填表：简单观察只需足够复现的短记录；强结论才补相应的统计/证明材料。
定义有限工作窗口，预先说明何种诊断触发适配，何种结果触发辨别或确认。
不将“首轮必须胜出”设为全部后续工作的统一门槛。

## 5. 实现与作业

Modeler 在独立分支/工作区实现最小改变，给 exact-zero/已知极限、单位、功率和因果输入核查。
Experimenter 在冻结源码/配置下执行，保留数据身份、初始化、RNG、优化器、数值与逐事件结果。
真实宿主负责启动/监控/恢复；本包工具只做记录和候选任务检查，不能声称后台自动推进。
任务分配见 [runtime](../agents/runtime.md)：冻结输入、同路径单写者、资源容量、独立审查。
长作业优先退出回调；仅在需要时轻量轮询。禁止多个 agent 反复解析同一大文件。

## 6. 五轴解释与下一动作

| 观察 | 合理下一动作 | 禁止跳跃 |
|---|---|---|
| 实现/数值证据无效 | 有界 repair 或结束无效 trial | 算法族被否定 |
| 梯度健康但曲线仍变化、充分性未知 | 有针对性的 adaptation 或暂存 | 健康=充分 |
| 探针不区分机制、信息不足 | discrimination / 可辨识性分析 | 再训练久一点必然解决 |
| 单次匹配正收益 | 预算内观察；视主张选择 confirmation | 稳健识别或自动晋升 |
| 单次无收益/混合结果 | 比较优化/探针/区间后选适配、辨别、确认或暂存 | 自动否定/强制无条件再跑 |
| 充分比较且区间支持实践等效 | 限定实例与协议的等效结论 | 机制不存在 |
| 精确反例且独立核对 | 否定对应数学命题 | 扩大到未覆盖模型族 |

确认需求与晋升资格是两个输出；阴性也可能高信息价值，阳性也可能暂不值得追。
结果后修改问题、优化目标或判据，必须新建前瞻修订并保持旧结果解释，不追溯“过门”。

## 7. 防止无止境适配与过早淘汰

两个连续 Run 只有参数微调/工程修复且未减少重要不确定性时，触发内部结构复盘。
root 判断：是否还有可区分预测、是否重复已有证据、是否存在更便宜的替代试验。
仍有新问题可在既有授权和新的有限协议内推进；没有则暂存并写重开条件。
此触发不是硬性“第二次失败即停”，不因常规内部复盘自动暂停找用户。
只有真实暂停、权限变更、无法获得必要资源/模型或核心目标不清时才形成外部阻碍。

每次追加适配要对抗至少一个具体混淆；不得通过改名、换 seed 或重启 optimizer
重置已用机会。重复修复应定位共同根因，不能无限以流程成功代替科学收获。

## 8. 闭合与下轮

分别记录代码、模型、科学三决定及证据；更新 Campaign 的当前认识、替代解释和下一问题。
保存负结果和工作候选，保护已接受锚点。成本、预算、执行状态分别收尾。
有新产物按研究政策归档并核验远端；未完成归档先恢复对账，再进入下一 Run。
最终报告回答：现在知道什么、仍不知道什么、下一笔投入能区分什么。
若范围已授权且未暂停，root 自主继续；不得把用户当每一轮的调度器。

## 9. 旧记录的兼容解释

旧 runner 原样保留以复现冻结实验。optimization_unresolved=False 只能迁移为
“未出现旧定义的健康报警”，新 adequacy 仍为 unknown，除非有额外可审查证据。
旧 NOT_RETAINED 保持不晋升含义，不升级为否证；旧余量关闭，不给新 Run 自动额度。
完整能力 L1/L2/L3 与上述证据轴分开，不再使用冲突的 L0–L4 命名。
